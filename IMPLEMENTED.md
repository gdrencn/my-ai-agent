# my-ai-agent 0.1.15 implementation

## Verified corrections

Native CA dependency detection first accepts already loaded CA certificates. With a lazy trust directory, it honors SSL_CERT_DIR or the OpenSSL default path list and checks readable subject-hash.N entries for parseable CA certificates. It does not count an existing directory, arbitrary PEM names, CRL names or leaf-only files as CA availability. Each candidate is parsed in an isolated SSLContext. Dependency detection is offline; normal HTTPS retains certificate-chain and hostname validation. No CA package, additional runtime library or bundled trust store is introduced.

A shared native HTTP endpoint formatter brackets IPv6 literals and maps IPv4/IPv6 wildcard listeners to the corresponding client loopback. Backend-specific environment parsing stays in its own adapter. llama.cpp listener arguments retain the configured bind address; Ollama keeps its native bind environment. Profiles, preload commands, readiness and read-only observations use correctly serialized addresses. Default IPv4, DNS names and explicit ports remain supported. Native services and codex-local remain independent of Maa runtime.
