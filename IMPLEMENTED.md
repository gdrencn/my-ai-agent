## Current architecture

maa is a one-shot installation/configuration tool. There is no maa daemon or Responses bridge. After a management command finishes, backend and Codex operation use only native executables and saved configuration.

| Requirement | Implementation and verification |
| --- | --- |
| Native autostart | Ollama uses its official ollama.service with an owned drop-in. llama.cpp uses a native llama-server.service. ExecStart runs only the official executable; native curl preloads the selected Ollama model. No Python, maa.pyz or manager callback is in a boot command. Only the accepted backend is enabled. |
| Independent local launcher | Shell script exports PATH with $HOME/.local/bin prepended to the inherited value, then directly execs codex --no-daemon --profile maa-local and forwards normal user arguments. It does not import maa, read manager state, rewrite profiles, reload models or proxy requests. The regression reproduces the old command-not-found error and verifies success with user bin absent from inherited PATH, spaces in HOME, literal arguments and unchanged exec PID. Fresh native tests immediately use both real backends after official installation with a system-only parent PATH, and remove the installed maa archive while using real Codex. Prior evidence covers both paused targets autostarting after container restart with the archive absent. |
| Separate native connections | Selection writes the corresponding native backend configuration and Codex profile. Ollama and llama.cpp each use their own /v1/responses endpoint; no common protocol converter is retained. The single active profile points to the selected backend. Per-backend/model settings remain separate. |
| Model identity | Profile, catalog and native request use the original model name. Ollama applies context settings to the public tag; native manifest copies preserve original presets and support rollback without copying model weights. ## Limits

Native protocols do not provide full Codex custom/freeform-tool compatibility. The local catalog therefore does not advertise freeform apply_patch; ordinary shell tools remain. Hosted search, namespace tools and reasoning effort support vary by backend/model and are not repaired by a maa proxy.

A preliminary direct qwen3:0.6b Codex run returned thinking without a final body. The native check correctly failed; other runs returned normal text. That model-competence failure is retained in evidence and is not converted into a successful result. The paired native suite uses qwen2.5:3b for the Ollama Codex path. Native function selection by a tiny model is not a general coding-quality guarantee.

No native MTP/recurrent-model inference, large qwen3.8 reproduction, partial-offload stability or performance acceptance is claimed. MTP/RS allocation classification uses source/log fixtures. Global host Codex files and host mas implementation are untouched. Disposable validation containers are removed after verification.
