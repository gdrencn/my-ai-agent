# my-ai-agent 0.1.16 implementation (test release candidate)

## Verified corrections

Saved native endpoints are resolved by one Controller method. It checks the accepted target fingerprint, native-unit ownership and saved configuration signature before using the persisted upstream URL. Existing 0.1.15 runtime records remain readable. Start, wake, readiness and observation use that address rather than rebuilding it from a later shell's environment. A new candidate or a changed native unit uses the current native environment; rollback restores the accepted configuration and address. Running Ollama inventory, pull and GGUF import also receive the saved endpoint explicitly. Replacing the current public tag invalidates model-parameter reuse while retaining a separate endpoint signature, so subsequent inventory does not silently move to the default port.

The common process runner now has an owned management mode. Native acceptance CLI calls use a private process group inside the caller's existing Linux session, preserving the controlling terminal needed by sudo. Foreground ownership and terminal modes are captured before spawning, handed to the command, and restored after cleanup on success, failure, timeout and interruption. This includes authentication that times out while echo is disabled. The existing PID/start-time checks and bounded TERM/KILL cleanup apply to that group, including a temporary Ollama server that survives its parent. Other process groups and independent systemd services are outside this scope. Codex clients continue to use the existing separate-session cleanup, including descendants that change groups. Live diagnostics, captured JSON stdout and native cancellation exit code 130 remain intact.

Official Ollama installer cleanup preserves an existing installation exception or KeyboardInterrupt, attaches a secondary cleanup diagnostic and reports it through the shared output module. Failed cleanup after a successful installer still fails. An interruption during cleanup retains cancellation semantics and the preceding installation error.

Eleven added tests cover saved endpoint wake/readiness/paused start/idle wake, candidate rollback, running inventory/pull/import after shell environment changes and tag invalidation, installer/cleanup error combinations, temporary Ollama cleanup after normal exit/failure/timeout/interruption, unrelated group survival, foreground restoration for fast commands, and sudo authentication/cancellation/timeout with piped stdin and captured stdout.

The three original isolated reproductions were repeated against the corrected paths: the native queries use the saved custom ports, cleanup preserves the original exceptions, and the timed-out temporary server is gone. The paired build is deterministic. Python 3.11 grammar, generated shell syntax, catalog parity and baseline coverage correspondence pass. Fixture processes use private files and fake backends; they do not establish actual backend, GPU or upstream sudo compatibility for this version.

All 42 native acceptance checks passed in both ordinary-user and root Linux environments with Git, real official backends, Codex 0.166.0 and GPU assertions. Real legacy 0.1.15 native configurations with custom ports upgraded to 0.1.16, then started and served actual Codex/nonstreaming/SSE conversations without the original environment. Explicit wake preserves the native instance; Ollama idle wake, failed-candidate rollback, native pull and inventory retain the saved custom endpoint. A real temporary Ollama server was observed during a native download and disappeared after timeout. Actual classic sudo 1.9.15p5 and sudo-rs 0.2.13 each passed password authentication, cancellation and authentication timeout with piped stdin, captured stdout, unchanged foreground ownership and restored terminal modes. No test password was echoed or retained in evidence. Public installer acceptance and publication remain the final pending stage; stable/0.1.9 remains unchanged.
